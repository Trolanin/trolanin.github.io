        What the simulator understands
        

          
Paste a normal Arduino sketch. It is translated to JavaScript and run against a virtual clock, so delay(), millis() and EVERY_N_MILLISECONDS keep real timing, and show() costs what a WS2812 costs (30 µs per pixel).

          
C++: functions, overloads, default arguments, structs and classes with constructors and methods, enums, typedefs, function-pointer tables, arrays, static locals, #define / #if, integer division, and uint8_t-style wraparound. Not supported: templates, lambdas, goto, raw pointer tricks beyond leds + n and &leds[n], and Arduino String methods.

          
FastLED: CRGB / CHSV and their operators, named colours, fill_*, fadeToBlackBy, blur1d, beatsin*, sin8 family, random8/16, inoise8, palettes and gradient palettes, CRGBArray ranges, brightness and power limiting.

          
NeoPixel: setPixelColor, Color, ColorHSV, gamma32, fill, rainbow, RGBW types.

          
Not simulated: WiFi, Bluetooth, I²C/SPI devices, files, FreeRTOS tasks. A sketch that needs them stops with a message naming what was missing. Colour correction and dithering are accepted but ignored.

          
Current is an estimate (20 mA per channel at full, 1 mA idle per pixel) — good for sizing a supply, not a measurement.

        

      

      

        Music-reactive sketches
        

          
Run led-audio.exe (in this folder). It captures whatever Windows is playing — no microphone, no virtual cable — and sends a 19-byte frame every 10 ms. "Audio bridge" in the header turns green when it's connected.

          
The frames arrive on Serial, exactly as they would on a real ESP32, so the same sketch runs on both: 0xFF, level, beat counter, then 16 bands from bass to treble, each 0–254. Start from the "Audio spectrum" example.

          
Real board: close the Arduino serial monitor, then run led-audio.exe --port COM5 (your port; --baud defaults to 115200, matching Serial.begin(115200)). The sim and the board can run at the same time.

          
The serial receive buffer is 256 bytes, as on the ESP32: a sketch that blocks for more than ~130 ms between reads drops frames here too.
